## 6. Ответы на контрольные вопросы

### 1. Что такое OpenTelemetry? Атрибуты, события, контекст, журналы, трассировки, показатели?

OpenTelemetry — это набор открытых инструментов, API и SDK для получения телеметрии приложений.

Основные понятия:

- **Атрибуты** — данные в виде пар «ключ — значение», описывающие операцию.
- **События** — записи о событиях внутри Span.
- **Контекст** — информация, которая передаётся между компонентами системы и связывает операции.
- **Журналы** — текстовые или структурированные записи о работе приложения.
- **Трассировки** — последовательности связанных операций при обработке запроса.
- **Метрики** — числовые показатели состояния и производительности системы.

### 2. Что такое наблюдаемость? Надёжность и показатели?

Наблюдаемость — это возможность понять внутреннее состояние системы на основании данных, которые она генерирует.

Для наблюдаемости используются метрики, журналы и трассировки.

Надёжность показывает способность системы выполнять свои функции без отказов.

Для оценки надёжности применяются показатели доступности, времени ответа, количества ошибок и производительности.

### 3. Что такое трассировка? Что такое распределённая трассировка?

Трассировка показывает последовательность выполнения операций в приложении.

Распределённая трассировка позволяет отслеживать один запрос при его прохождении через несколько сервисов.

Каждая операция представляется Span. Несколько связанных Span образуют Trace.

Для сбора распределённых трассировок используются инструменты OpenTelemetry и передача контекста между сервисами.

Основные проблемы: сетевые задержки, неполная передача контекста, ошибки между сервисами и большой объём телеметрии.

### 4. Сигналы OpenTelemetry: трассировки, метрики, логи?

OpenTelemetry поддерживает три основных сигнала:

- **Traces** — показывают последовательность и длительность операций.
- **Metrics** — показывают числовые характеристики системы.
- **Logs** — содержат записи о событиях и ошибках.

Совместное использование этих сигналов помогает обнаруживать проблемы и находить их причины.

### 5. Инструменты OpenTelemetry: автоматические, ручные, библиотеки?

В OpenTelemetry существуют два основных способа инструментирования.

**Автоматическое инструментирование** добавляет сбор телеметрии без существенного изменения исходного кода.

**Ручное инструментирование** выполняется разработчиком с использованием API и SDK.

Библиотеки инструментирования позволяют подключать OpenTelemetry к Flask, Django, базам данных и другим компонентам.

В данной работе использовались автоматическая трассировка Flask и ручное создание Span `calculate-sum`.

### 6. Компоненты OpenTelemetry: спецификация, сборщики, библиотеки инструментальных средств, экспортёры?

Основные компоненты OpenTelemetry:

1. **Specification** — определяет стандарты API, SDK и форматов телеметрии.
2. **API и SDK** — используются для создания и обработки данных.
3. **Instrumentation Libraries** — собирают данные из приложений и библиотек.
4. **Exporters** — отправляют данные в другие системы.
5. **OpenTelemetry Collector** — принимает, обрабатывает и передаёт телеметрию.

В нашей работе трассировки передавались непосредственно в Jaeger с помощью OTLP-экспортёра.

### 7. Ресурс OpenTelemetry (телеметрия)?

Resource в OpenTelemetry — это набор атрибутов, описывающих источник телеметрии.

Например:

- `service.name`
- `service.version`
- `service.instance.id`

В данной работе использовалось имя сервиса:

`service.name = lab3-flask-group13`

Это позволяет найти трассировки конкретного приложения в Jaeger.

### 8. Экспортёры OpenTelemetry?

Экспортёр — это компонент, который отправляет телеметрию из приложения в систему обработки или хранения.

Например, OTLP Exporter передаёт данные по протоколу OpenTelemetry Protocol.

Существуют экспортёры для трассировок, метрик и журналов.

В данной работе использовался `OTLPSpanExporter`, который отправлял трассировки в Jaeger.

### 9. Что такое Prometheus? Как работает Prometheus?

Prometheus — это система мониторинга и хранения временных рядов.

Она собирает метрики приложений, обычно периодически опрашивая HTTP-эндпоинты с метриками.

Полученные данные сохраняются с временными метками.

Для анализа используется язык запросов PromQL.

Prometheus помогает наблюдать за нагрузкой, ошибками, производительностью и доступностью приложений.

### 10. Концепции Prometheus?

Основные концепции Prometheus:

- **Metric** — измеряемый показатель.
- **Time Series** — последовательность значений с временными метками.
- **Labels** — дополнительные характеристики метрик.
- **Target** — источник метрик.
- **Scrape** — процесс сбора метрик.
- **Exporter** — компонент, предоставляющий метрики.
- **PromQL** — язык запросов.
- **Alerting Rules** — правила обнаружения проблем.

### 11. Типы метрик?

В Prometheus используются четыре основных типа метрик:

1. **Counter** — монотонно увеличивающийся счётчик, который может сбрасываться при перезапуске.
2. **Gauge** — значение, которое может увеличиваться и уменьшаться.
3. **Histogram** — распределение наблюдений по диапазонам.
4. **Summary** — статистика наблюдений, включая количество, сумму и при настройке квантили.

Например, Counter можно использовать для количества запросов, а Gauge — для объёма используемой памяти.

В OpenTelemetry также применяются инструменты Counter, UpDownCounter, Histogram и Gauge.

### 12. Запрос и преобразование данных Grafana?

Grafana позволяет выполнять запросы к подключённым источникам данных и отображать результаты на панелях мониторинга.

Например, для Prometheus используется PromQL, а для Loki — LogQL.

Grafana также поддерживает преобразования результатов:

- фильтрацию полей;
- группировку;
- вычисление новых полей;
- объединение данных;
- сортировку.

Это позволяет создавать удобные графики и таблицы.

### 13. Источники данных Grafana?

Источник данных Grafana — это система, из которой Grafana получает информацию для визуализации.

Примеры:

- Prometheus — метрики.
- Loki — журналы.
- Jaeger — трассировки.
- PostgreSQL — данные из базы данных.
- Elasticsearch — поиск и анализ данных.

Grafana может работать с несколькими источниками одновременно.

### 14. Панели мониторинга Grafana?

Dashboard — это страница Grafana, содержащая несколько визуальных панелей.

Панели могут отображать:

- графики;
- таблицы;
- статистические показатели;
- журналы;
- временные ряды.

Dashboard помогает наблюдать за состоянием системы в одном интерфейсе.

### 15. Процесс обработки журналов Grafana Loki?

Grafana Loki — система сбора и хранения журналов.

Общий процесс работы:

1. Приложение создаёт записи журнала.
2. Агент собирает эти записи.
3. Журналы отправляются в Loki.
4. Loki сохраняет данные и индексирует наборы меток.
5. Grafana выполняет запросы через LogQL и отображает результаты.

Loki ориентирован на эффективное хранение журналов и поиск по меткам.

### 16. Варианты сборки журналов для Grafana Loki?

Журналы можно собирать несколькими способами:

1. С помощью Grafana Alloy.
2. Через OpenTelemetry Collector.
3. Из журналов Docker-контейнеров.
4. Из файлов журналов приложений.
5. Через приложения, отправляющие логи непосредственно в поддерживаемый интерфейс приёма.

Ранее для сбора журналов широко использовался Promtail.

Выбор способа зависит от инфраструктуры и требований системы.
